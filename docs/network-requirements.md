# Custom Companion Network Requirements

This document identifies the network endpoints used by the Custom Companion macros and Companion Installer. It groups each endpoint by the feature that introduces it so Device Administrators can prepare routing, DNS, firewall, proxy, and certificate policies for the parts of the solution they intend to use.

Unless a deployment explicitly uses another port, HTTPS and secure WebSocket connectivity normally use TCP 443.

## Macro Core Needs

These endpoints support communication between registered Companion Devices and Parent Room Devices. They are used when Parent Room Registration, Paired operation, provisioning, standby synchronization, or call coordination requires communication with another RoomOS device.

| Endpoint group | Network endpoint | Purpose | When required |
| --- | --- | --- | --- |
| Parent Room identity | `https://{registered-parent-host}/getxml?location=/Status/SystemUnit` | Reads Parent Room Device identity during registration and connectivity validation. | When registering or validating a Parent Room Device. |
| Parent Room standby | `https://{registered-parent-host}/getxml?location=/Status/Standby/State` | Reads the selected Parent Room Device standby state for synchronization. | When standby synchronization applies to the selected Parent Room Device. |
| Registered-device call state | `https://{registered-device-host}/getxml?location=/Status/Call` | Reads current call state used by supported call coordination. | When call synchronization or admission validation needs current device call state. |
| Registered-device command transport | `https://{registered-device-host}/putxml` | Carries macro provisioning, configuration, peripheral connection, heartbeat, and Custom Companion messages between registered devices. | When Parent Room functionality is active. |

`{registered-parent-host}` and `{registered-device-host}` are the administrator-supplied hostnames or IP addresses saved through Parent Room Registration and Companion Device Callback configuration. Traffic can run from the Companion Device to a Parent Room Device or from a Parent Room Device to its registered Companion Devices, depending on the workflow.

## Optional Macro Network Features

These endpoints are introduced by configurable user-interface features. The core Companion Device and Parent Room Device transport described above does not depend on them.

| Endpoint group | Network endpoint | Purpose | Current default and control |
| --- | --- | --- | --- |
| **Simple-WebWidget — application** | `https://ctg-tme.github.io/Simple-WebWidget/` | Hosts the managed Companion WebWidget and its application assets. | Enabled by `UserInterface.WebWidget.CompanionWidget.enabled: true`. Set it to `false` before initial deployment to omit solution management of the widget, or replace its base URL with `UserInterface.WebWidget.urlOverride`. |
| ↳ Simple-WebWidget — weather | `https://api.open-meteo.com/v1/forecast` | Supplies the weather displayed by Simple-WebWidget. | Introduced when `CompanionWidget.weather.mode: true`. Set it to `false` to omit weather requests while retaining the widget. |
| ↳ Simple-WebWidget — usage events | `https://us.aptabase.com/api/v0/event` | Receives usage events generated by the current hosted Simple-WebWidget build. | Introduced by the current Simple-WebWidget build. Disable or replace the managed widget to remove this endpoint requirement. |
| ↳ Simple-WebWidget — alternative event region | `https://eu.aptabase.com/api/v0/event` | Provides the alternative Aptabase region supported by Simple-WebWidget builds configured for the EU region. | Used only when the selected Simple-WebWidget build is configured for the EU region; the current hosted build uses the US region. |
| ↳ Simple-WebWidget — branding image | `https://ctg-tme.github.io/Custom_Companion_2026/icons/custom-companion-512.png` | Supplies the prefilled Standalone and Paired images shown by Simple-WebWidget. The UI module independently uses the same release-owned URL for the custom Companion Device Select panel icon. | `Standalone.iconUrl` and `Paired.iconUrl` can select different WebWidget images. They do not change or disable the panel icon. |

The current configuration enables the managed Simple-WebWidget in both Standalone and Paired modes because `CompanionWidget.enabled` is `true` and `restoreStandaloneExisting` is `false`. Weather and time are enabled; the clock uses the device browser locally and does not introduce another endpoint. Both mode-specific `iconUrl` values are prefilled with the release-owned branding image.

Open-Meteo and Aptabase are downstream services introduced by the optional Simple-WebWidget. They are not direct RoomOS HTTPClient destinations in the Custom Companion macros. Omitting or replacing Simple-WebWidget removes its downstream endpoint requirements; weather can also be disabled independently. If solution management is disabled after `cc26WebWidget` has already been saved on a device, remove or replace that existing RoomOS WebWidget separately.

## Web Installer

These endpoints support the hosted Companion Installer, source selection, release preflight, and its authenticated connection to a Companion Device.

| Endpoint group | Network endpoint | Purpose | When required |
| --- | --- | --- | --- |
| Companion Installer and Main Fork | `https://ctg-tme.github.io/Custom_Companion_2026/` | Hosts the installer application, packaged README, Main Fork snapshot, Release Manifest, macro sources, and release-owned icon. | Required when using the hosted installer or its packaged Main Fork. |
| GitHub release discovery | `https://api.github.com/repos/ctg-tme/Custom_Companion_2026/releases` | Discovers published stable and preview releases. | Accessed when the installer loads. Main Fork remains selectable if release discovery is unavailable. |
| GitHub release resolution | `https://api.github.com/repos/ctg-tme/Custom_Companion_2026/commits/{release-tag}` | Resolves a selected release tag to its commit SHA. | When a tagged stable or preview release is selected. |
| Tagged project resources | `https://raw.githubusercontent.com/ctg-tme/Custom_Companion_2026/{commit-sha}/{resource}` | Retrieves the Release Manifest and macro sources from the resolved release commit. | When installing a tagged release rather than the packaged Main Fork. |
| Memory-Storage dependency | `https://raw.githubusercontent.com/ctg-tme/Memory-Storage-Functions-V2/main/Memory-Storage-Functions-V2.js` | Retrieves the external Memory-Storage macro declared by the Release Manifest. | During source preflight for the current manifest. |
| Companion Device JSXAPI | `wss://{companion-device-host}` | Provides the single authenticated browser-to-Companion Device session used for identity checks, configuration, installation, log monitoring, and optional Parent Room inventory, registration, and deregistration. | Required while the installer is connected to a Companion Device. |
| Companion Device certificate trust | `https://{companion-device-host}` | Opens the Companion Device web interface so the browser can establish trust in its HTTPS certificate before the secure WebSocket connection. | User initiated when certificate trust must be established. |
| Installer team image | `https://avatars.githubusercontent.com/u/159071680?s=200&v=4` | Supplies the Collaboration TME team image displayed by the installer. | Loaded with the hosted installer interface; it is not used for device installation commands. |

`{release-tag}`, `{commit-sha}`, `{resource}`, and `{companion-device-host}` are resolved from the selected release and administrator input. The installer connects directly to the Companion Device and never opens its own direct connection to a Parent Room Device.

## Scope Notes

- Standard RoomOS cloud connectivity, including the Cisco Webex services used when RoomOS executes `Webex.Join`, remains governed by the device's Cisco RoomOS network requirements. The macros do not define fixed Webex cloud URLs.
- Documentation and source links opened by a user are not required for macro or installer operation and are not listed as runtime endpoints.
- npm registry access and GitHub Actions endpoints are build and deployment infrastructure, not runtime requirements for the hosted installer or installed macros.
- A locally hosted Companion Installer uses its local origin in place of the project GitHub Pages origin. Release discovery and tagged-resource behavior remain the same unless the local build is modified.
